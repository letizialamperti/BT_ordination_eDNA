# Pilot audit — 18 November 2026

Scope: inner BT pilot, fixed/shuffled launchers, frozen embedding export and
fixed-budget downstream classification. No real study results were recalculated.

## Corrections

| Finding | Implemented safeguard |
| --- | --- |
| Two jobs could write the same run | Exclusive advisory filesystem lock for training and export; separate classifier output lock |
| Export roles were not checked against training | Every exported ID, role and spatial block must match the frozen training roles; outer IDs are rejected |
| CSV cleanup differed between training and export | String-preserving input, whitespace trimming, identical missing-read markers |
| Resume did not track raw input changes | Raw input size/mtime and hashes of trainer, checks, dataset, model, representation and mapper compared on resume |
| Duplicate or overlapping split assignments used assertions | Explicit validation with informative exceptions, active even under Python optimization |
| Startup checked chunk counts without exercising reads | Setup reads first and last indexed views from training and validation and checks tensor shape |
| Non-finite losses could propagate | Stop on non-finite training loss before backward; check available validation metrics |
| Environment startup/export diagnostics still went directly to shared storage | Shared launcher helper redirects stdout/stderr to node-local logs before conda activation; unbuffered Python and faulthandler enabled |
| Log-copy failure could obscure the training exit status | Exit handler preserves original status even if shared-storage copy fails; handles TERM/INT |
| Classifier accepted arbitrary sample sets with suitable role strings | Exact sample and role match against frozen classifier cohort; explicit finite-value and target checks |
| Interrupted saves could leave versioned epoch files that enter the comparison twice | All-checkpoint export rejects versioned/duplicate epoch names and requests explicit resolution |

The revised bundle must be transferred in full, including pilot_checks.py and
job_logging.sh. Source changes intentionally invalidate resume from runs created
with a different trainer; the io_retry output root preserves earlier attempts.
A run that failed before producing last.ckpt still needs a fresh output root.

## Reproducible checks

verify_pipeline.py exercises the actual BT dataset, representation, projector,
optimizer and frozen exporter imported from the BT repository. Synthetic input
uses short sequences and small subsets on CPU; representation/projector outputs
remain 256D/64D. The excluded outer CSV is deliberately absent.

The suite checks 1,764 batch boundary combinations; invalid roles and competing
writers; indexed-read preflight; fixed and shuffled training; every-epoch and
initial checkpoints; two validation scores; exact equality of resumed versus
uninterrupted CPU model weights; identical initial states across view modes;
scratch cleanup; embedding export and verified cache reuse; rejected outer IDs;
and 18 classifier runs (two checkpoints, three targets, three seeds).

Machine-readable reports are audit_report.json and audit_report_workers2.json.
Both suites passed. Each records tested script hashes. The two-worker check
preceded the final exporter-only ambiguity guard and its synthetic test; the
zero-worker report covers that final addition. Multiprocessing-related code was
unchanged after the two-worker check.
The test reference BT sources were fetched from letizialamperti/BT_ordination_eDNA
main. The server's installed copies are identified in startup logs and run config.

Separate shell checks passed for normal completion, exit 7, TERM (143), and a
failed copy-back destination (original exit 5 retained). Shell syntax passed for
all pilot launchers. Python syntax compilation passed for all pilot scripts.

## Limits and server checks

CPU tests cannot establish full-size CUDA memory use, the behavior of all 12
server workers, node-local free capacity or Bettik/BeeGFS availability. Normal
training still reads original CSVs and writes checkpoints/CSV metrics on shared
storage. Forced SIGKILL or node loss can prevent final log copy-back. The pilot
has one inner rotation and one encoder seed; these checks establish software
consistency, not statistical sufficiency of the scientific comparison.

On the server, keep the provided absolute BT_REPO and /var/tmp settings, inspect
the printed module paths and environment, and verify the new node-local logs if
the filesystem fails again. Training does its own raw-data preflight; --check-only
can perform that scan independently without GPU training.
